# Résumé and AIMeer Model Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the top résumé control compact and discoverable, add subtle press feedback, and give AIMeer a theme-safe cloud/local switch with conservative Android eligibility routing.

**Architecture:** Add a small browser/CommonJS-compatible device policy helper for deterministic routing tests. Add the segmented control and résumé tooltip to the existing HTML/CSS, then update `chatbot.js` so explicit mode choices, eligibility explanations, and active download cancellation all flow through the existing route/state machine.

**Tech Stack:** Hand-written HTML, CSS custom properties, plain JavaScript IIFEs, Node’s built-in `assert` runner, local HTTP preview on port 8080.

## Global Constraints

- No framework, build step, package manager, or new external dependency.
- English remains the DOM source of truth; new visible copy needs `data-i18n` and matching Bahasa Melayu in `assets/js/i18n.js` where applicable.
- The only approved external runtime dependency remains WebLLM from `esm.run`.
- Local model eligibility must keep the existing WebGPU adapter and `maxBufferSize >= 1.5 GB` check.
- iOS/iPadOS always use cloud; unknown and mid/low-range Android defaults to cloud.
- Light-theme changes must be reflected in both light palette blocks if a new color token is needed.
- Preserve unrelated user changes, including the untracked `AGENTS.md`.
